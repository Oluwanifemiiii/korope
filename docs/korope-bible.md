**INTRODUCTION**

Korope is not simply another e-hailing application.

It is the modernization of one of Nigeria\'s most recognizable transport
systems.

For decades, the yellow minibus, popularly called the \"Korope\" has
symbolized movement, hustle, resilience, and connection across Lagos.
Yet the experience around it has often been fragmented, unpredictable,
and stressful. Korope seeks to preserve the accessibility and efficiency
of shared transport while transforming the experience into one defined
by trust, comfort, technology, and dignity.

The goal is not to replace public transport. The goal is to elevate it.

Korope is a mobility platform designed specifically for the realities of
African cities, beginning with Lagos. It combines route intelligence,
real-time tracking, digital payments, structured operations, and
intuitive user experience to create a transportation service that feels
organized without losing the flexibility commuters value.

The application should instantly communicate professionalism and
reliability while remaining approachable and familiar. Every interaction
should reassure users that they are in control of their journey.

**PRODUCT VISION**

Korope exists to become the most trusted urban mobility platform in
Africa.

The platform should eventually become much more than a booking
application.

It should evolve into an ecosystem including:

-   Shared commuter transport

-   Premium commuter subscriptions

-   School transportation

-   Staff transportation

-   Estate mobility

-   Airport transfers

-   Event shuttles

-   Tourism transportation

-   Fleet management

-   Mobility analytics

-   Smart city integrations

The first impression of the application should immediately communicate:

\"This is the future of African transportation.\"

**MISSION**

To make daily commuting safe, predictable, affordable, and enjoyable
through intelligent technology and exceptional design.

**LONG-TERM AMBITION**

Five years from launch, someone in Lagos should naturally say:

\"Book a Korope.\"

in the same way people currently say

\"Order an Uber.\"

That level of brand recognition requires every design decision to
reinforce trust, consistency, and ease of use.

**CORE PHILOSOPHY**

Korope is built upon six foundational principles.

**1. Predictability**

Every commuter should know what is happening before it happens.

No surprises.

Arrival times.

Bus location.

Seat availability.

Stops.

Pricing.

Everything should be transparent.

**2. Simplicity**

The application must remove friction rather than introduce it.

Users should never need instructions.

Every interaction should feel obvious.

If something requires explanation, redesign it.

**3. Confidence**

The interface should never appear uncertain.

Animations should feel deliberate.

Buttons should feel solid.

Maps should feel stable.

Typography should feel organized.

Users should feel guided instead of rushed.

**4. Human-Centered Mobility**

Technology exists to reduce stress.

Not to impress.

Every screen should answer the user\'s primary question:

\"What do I need right now?\"

**5. Respect for Time**

Time is the most valuable asset of every commuter.

Every feature should either:

-   reduce waiting

-   reduce confusion

-   reduce walking

-   reduce uncertainty

If it doesn\'t, reconsider whether it belongs.

**6. Local Intelligence**

Korope should understand Lagos better than any international mobility
platform.

It should recognize:

Estate gates.

Landmarks.

Popular junctions.

Bus parks.

Commercial hubs.

Markets.

Universities.

Business districts.

Schools.

Instead of relying solely on formal addresses, the platform should

**EMOTIONAL EXPERIENCE**

Every interaction within the application should evoke one or more of the
following emotions:

**Safety**

The user should feel protected.

Vehicle information, driver identity, trip progress, and emergency tools
should always be easy to find without dominating the interface.

**Relief**

Booking a commute should reduce anxiety.

The app should replace uncertainty with clarity at every step.

**Progress**

Users should feel that they are moving toward their destination
efficiently.

Motion, progress indicators, and route updates should reinforce forward
movement.

**Familiarity**

Although technologically advanced, the interface should feel culturally
familiar.

Language, landmarks, and commuting patterns should reflect how people in
Lagos actually travel.

**Pride**

Using Korope should feel aspirational.

Passengers should be proud to say they use it because it represents a
modern Nigerian solution built for African cities.

**DESIGN PRINCIPLES**

The visual and interaction design of Korope should consistently follow
these principles:

-   **Clarity over decoration**: Every visual element must have a
    purpose.

-   **Maps first**: The map is the primary stage where journeys unfold;
    other information should support it, not overshadow it.

-   **Progressive disclosure**: Reveal information only when it is
    needed. Keep the interface clean while allowing users to drill down
    for more details.

-   **Motion with meaning**: Every animation should communicate state
    changes, not exist for spectacle.

-   **Touch-friendly design**: Buttons and controls should be
    comfortable to use while walking or standing in a crowded
    environment.

-   **Trust through consistency**: Reuse familiar interaction patterns
    throughout the app so users build confidence quickly.

-   **Contextual intelligence**: Surface the most relevant actions based
    on time of day, recent trips, and recurring commute habits.

**DESIGN COMMANDMENTS**

Every designer contributing to Korope should follow these rules:

1.  Never add an element without a purpose.

2.  Favor clarity over decoration.

3.  Preserve map context whenever possible.

4.  Use motion to explain, not entertain.

5.  Make the primary action obvious on every screen.

6.  Respect the commuter\'s time---reduce taps whenever possible.

7.  Every screen should answer the user\'s next question before they ask
    it.

8.  Design for one-handed use first.

9.  Celebrate successful actions with subtle positive feedback.

10. Build a distinctly African product with world-class execution, not a
    copy of an existing global app.

-   Book a recent commute

-   Check active trip

-   View driver details

-   Add money

**RESPONSIVE BEHAVIOR**

Design should adapt without breaking hierarchy.

**Small phones**

Reduce vertical spacing.

Keep button height.

Increase scrolling.

**Large phones**

Allow cards to breathe.

Expand map area.

Increase margins slightly.

**Tablets**

Two-column layouts where appropriate:

Map \| Booking

Wallet \| Transactions

Profile \| Settings

Never simply scale up mobile screens.

Recompose them.

**DESIGN-TO-DEVELOPMENT HANDOFF**

Every screen should include annotations for developers.

For example:

**Interaction**

-   Bottom sheet opens to half state on first load.

-   Dragging upward expands to full state.

-   Swipe down collapses unless a text field is focused.

**Animation**

-   Spring easing

-   250ms

-   Shared element transition from Bus Card to Live Trip.

**Data**

-   Seat availability updates every 15 seconds.

-   ETA recalculates when traffic changes.

-   Wallet balance refreshes after successful payment.

This reduces ambiguity during implementation.

**FIGMA LIBRARIES**

Split reusable assets into libraries:

1.  **Foundation Library** -- colors, typography, spacing, icons.

2.  **Core Components Library** -- buttons, inputs, cards, navigation.

3.  **Mobility Components Library** -- bus cards, route timelines, seat
    maps, QR modules.

4.  **Marketing Assets Library** -- illustrations, onboarding graphics,
    promotional elements.

Teams can then update shared components without affecting unrelated
work.

**THE \"NO ORPHAN COMPONENT\" RULE**

Every component must answer:

-   Where is it used?

-   Which screens use it?

-   Which variant should engineers implement?

-   What replaces it if deprecated?

If a component has no clear purpose or no active usage, archive it
instead of leaving it in the production library.

**DESIGN SYSTEM GOVERNANCE**

As Korope grows, assign ownership.

-   **Design System Lead** -- maintains foundations and components.

-   **Product Designers** -- consume and request new components.

-   **Engineers** -- validate implementation fidelity.

-   **QA** -- verifies design matches production.

-   **Product Manager** -- approves additions that impact user
    experience.

The design system is a product of its own and should be versioned,
documented, and reviewed regularly.
